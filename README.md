# Weather Viewer

Weather Viewer — серверное веб-приложение для поиска городов и просмотра текущей погоды.

Пользователь может зарегистрироваться, войти в аккаунт, найти нужную локацию через OpenWeather API, добавить её в свой список, посмотреть текущую погоду и удалить сохранённую локацию.

## Возможности

### Аутентификация

* регистрация пользователей;
* вход в аккаунт;
* выход из аккаунта;
* собственная система сессий;
* аутентификация через cookie `SESSION_ID`;
* ограниченное время жизни сессии;
* автоматическое удаление просроченных сессий.

Сессии хранятся в PostgreSQL и связаны с пользователями. Проверка аутентификации выполняется на уровне приложения.

### Работа с локациями

* поиск локаций по названию;
* получение подходящих вариантов через OpenWeather Geocoding API;
* добавление выбранной локации в личный список пользователя;
* защита от повторного добавления одной и той же локации;
* удаление сохранённых локаций;
* хранение координат локации в PostgreSQL.

### Погода

Для каждой сохранённой локации приложение получает актуальные данные о погоде через OpenWeather API.

Отображается:

* название локации;
* текущая температура;
* влажность;
* погодные условия;
* иконка погоды.

### Валидация и обработка ошибок

Приложение проверяет пользовательский ввод и отображает понятные сообщения при ошибках, например:

* некорректные данные при регистрации;
* логин уже занят;
* локация уже была добавлена;
* некорректный поисковый запрос;
* сессия отсутствует или истекла.

### Controller

Контроллеры принимают HTTP-запросы, обрабатывают данные форм и передают данные в представления Thymeleaf.

Отдельные контроллеры отвечают за:

* главную страницу;
* регистрацию;
* вход;
* выход;
* поиск локаций;
* добавление локаций;
* удаление локаций.

### Service

Бизнес-логика отделена от HTTP-слоя и работы с базой данных.

Сервисный слой отвечает за:

* регистрацию и аутентификацию;
* управление сессиями;
* работу с локациями;
* взаимодействие с внешним погодным API.

### Repository

Repository-слой инкапсулирует работу с PostgreSQL через JPA/Hibernate.

Основные сущности:

* `User`;
* `Location`;
* `Session`.

### Клиенты внешнего API

Взаимодействие с OpenWeather вынесено в отдельные компоненты.

Приложение выполняет два основных внешних запроса:

```text
Название города
      |
      v
OpenWeather Geocoding API
      |
      v
Latitude / Longitude
      |
      v
OpenWeather Current Weather API
      |
      v
Текущая погода
```

Такой подход позволяет отделить работу с HTTP API от основной бизнес-логики приложения.

## Аутентификация и сессии

В приложении реализована собственная система сессий.

После успешной регистрации или входа:

1. создаётся новая сессия с UUID;
2. сессия сохраняется в PostgreSQL;
3. идентификатор сессии передаётся клиенту через cookie `SESSION_ID`;
4. браузер отправляет cookie при следующих запросах;
5. фильтр аутентификации проверяет существование и срок действия сессии;
6. по сессии определяется текущий пользователь.

Схема:

```text
Browser
   |
   | SESSION_ID
   v
SessionAuthenticationFilter
   |
   v
SessionService
   |
   v
SessionRepository
   |
   v
PostgreSQL
```

Если сессия отсутствует или истекла, пользователь не считается аутентифицированным.

Просроченные сессии также периодически удаляются из базы данных с помощью scheduler.

## Тестирование

В проекте реализованы интеграционные тесты основных компонентов приложения.

### Работа с базой данных

Интеграционные тесты проверяют взаимодействие между:

```text
Service
   |
   v
Repository
   |
   v
Hibernate
   |
   v
PostgreSQL
```

Проверяются сценарии:

* успешная регистрация пользователя;
* создание сессии после регистрации;
* регистрация пользователя с уже существующим логином;
* работа с просроченными сессиями;
* удаление просроченных сессий.

Для интеграционных тестов используется отдельная тестовая база PostgreSQL.

### Тестирование OpenWeather-клиента

HTTP-клиент тестируется с помощью `MockRestServiceServer`.

Во время теста реальный запрос к OpenWeather не выполняется.

```text
Integration Test
      |
      v
OpenWeather Client
      |
      v
MockRestServiceServer
      |
      v
Подготовленный JSON
```

Тесты позволяют проверить:

* корректность сформированного HTTP-запроса;
* HTTP-метод;
* десериализацию JSON;
* преобразование ответа в Java-объекты.

## Конфигурация

Для подключения к PostgreSQL и OpenWeather используются переменные окружения.

Пример:

```bash
USER_DB_NAME=postgres
DB_PASSWORD=your_database_password
OPENWEATHER_API_KEY=your_openweather_api_key
```

Основная база данных:

```text
app_db
```

Подключение:

```text
jdbc:postgresql://localhost:5432/app_db
```

Перед первым запуском необходимо создать базу данных:

```sql
CREATE DATABASE app_db;
```

После запуска Flyway автоматически применит необходимые миграции.

## Запуск проекта

Клонировать репозиторий:

```bash
git clone https://github.com/Kamil1developer/spring-weather-viewer.git
cd spring-weather-viewer
```

Настроить PostgreSQL и необходимые переменные окружения.

Собрать проект:

```bash
mvn clean package
```

После сборки Maven создаст WAR-файл:

```text
target/weather-viewer.war
```

WAR необходимо развернуть в Apache Tomcat.

Например:

```text
<TOMCAT_HOME>/webapps/
```

После запуска Tomcat приложение будет доступно примерно по адресу:

```text
http://localhost:8080/weather-viewer/
```

## Основные архитектурные решения

### Server-side rendering

Приложение использует классическую схему Spring MVC + Thymeleaf.

HTML формируется на сервере, а отдельный frontend-клиент не требуется.

### Собственное управление сессиями

Сессии являются отдельными сущностями приложения и сохраняются в PostgreSQL.

Это позволяет явно контролировать:

* создание сессии;
* время её жизни;
* проверку аутентификации;
* завершение сессии;
* удаление просроченных записей.

### Flyway для управления схемой БД

Изменения структуры базы данных выполняются через миграции Flyway.

Hibernate используется для ORM и работы с сущностями, а изменение схемы остаётся ответственностью Flyway.

### Dependency Injection для HTTP-клиентов

`RestClient` передаётся клиентам внешнего API через Dependency Injection.

Клиент не создаёт HTTP-инфраструктуру самостоятельно.

Это упрощает тестирование и позволяет использовать тот же клиент вместе с `MockRestServiceServer`.

### Хранение координат локаций

Локации сохраняются с `latitude` и `longitude`.

Название используется для отображения пользователю, а координаты позволяют однозначно определить географическое место и использовать его при запросе текущей погоды.
